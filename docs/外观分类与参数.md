# 外观分类与参数

外观页按「界面层级」分成四类，终端配色不在外观页，它挪到了设置 › 终端
（与字体、预览同页）。新界面先判断属于哪一类，再读对应的全局令牌，不要
自己拼 alpha，也不要单独新增滑杆。

令牌定义在 `src/settings/appearance_tokens.rs`，滑杆值在
`src/model.rs::Appearance`，设置页在 `src/settings/appearance.rs`。

## 一、四类界面

| 分类 | 包含的界面 | 读取的令牌 |
|---|---|---|
| 玻璃 | 顶栏、主机侧栏、右侧栏、标签栏、工作区容器、命令片段侧栏 | `UiTokens.glass`（顶栏 ×0.92、标签栏 +0.06/+0.16/+0.30 为内部常量） |
| 轻量浮层 | 右键菜单、下拉、Tooltip、Toast、终端查找栏、SFTP 拖拽幽灵 | `UiTokens.overlay`，菜单/下拉用 `theme::overlay()` |
| 模态弹窗 | 新建/编辑主机、确认弹窗、密码/键盘交互提示、SFTP 冲突与新建/删除、命令片段编辑 | `UiTokens.modal`；遮罩单独读 `UiTokens.backdrop` |
| 背景 | 壁纸铺满、清晰度遮罩、壁纸预模糊、设置页预览 | `UiTokens.clarity`、`UiTokens.blur` |

### 不进入外观分类的内容层

输入框、文本域、分段控件、预览块、壁纸卡片、规则表、状态点与各种语义色
（`FOAM` / `GOLD` / `LOVE`）属于内容与状态，不跟随玻璃变化。它们使用
`src/theme.rs` 里的命名常量（`FIELD_TINT`、`PREVIEW_TINT`、`CARD_TINT`、
`QUEUE_TINT`、`ROOT_TINT`、`PANEL_TINT`），保持对比度与语义稳定。

## 二、参数

| 分类 | 参数 | 范围 | 默认 | 实际作用 |
|---|---|---:|---:|---|
| 玻璃 | 不透明度 | 5–90% | 5% | 所有常驻结构面的底色 alpha（颜色为 `GLASS_RGB`，与纯色背景 `BASE_RGB` 不同，所以没有壁纸时也能看见变化） |
| 轻量浮层 | 不透明度 | 30–92% | 45% | `theme::overlay()`：`OVERLAY_RGB`（0x1c1930）叠到该 alpha |
| 模态弹窗 | 弹窗不透明度 | 38–98% | 52% | `MODAL_RGB`（0x1a1728）叠到该 alpha；低于 50% 时设置页提示对比度风险 |
| 模态弹窗 | 遮罩不透明度 | 0–90% | 50% | 弹窗背后整页压暗的程度 |
| 背景 | 壁纸 | — | 纯色 | 图片复制进 `data/`，设置存相对路径；支持 PNG/JPEG/WebP/BMP/GIF（GIF 取第一帧） |
| 背景 | 清晰度 | 0–100% | 65% | 越高暗色遮罩越淡 |
| 背景 | 壁纸模糊 | 0–30 px | 10 px | 只对壁纸做预模糊；无壁纸时滑杆禁用 |
| 终端配色 | 主题（设置 › 终端） | 默认 / Tokyo Night / Catppuccin Mocha | Rosé Pine Moon | 决定默认前景/背景、光标、选区与 ANSI 16 色；「默认」就是界面自己的 Rosé Pine Moon（`BASE_RGB` `#232136` / `TEXT` `#e0def4` 同源）。卡片只画名字与 16 色，字体与配色的效果统一看终端页末尾的「预览」 |

规则：

- 滑杆上的数字就是最终 alpha；派生的 ×/＋ 比例是内部常量，不再暴露。
- GPUI 没有逐面板背景模糊，浮层与弹窗靠不透明度保证可读性；这条原因只写在文档里，界面上不解释。
- 壁纸是所有界面的底色：玻璃、浮层、弹窗、遮罩都叠在壁纸上，没有哪一层用
  纯色底。要让浮层与弹窗更透，配色的做法不是只降 alpha，而是把底色压深
  （`OVERLAY_RGB` / `MODAL_RGB` 都比 `GLASS_RGB` 暗得多）：同样的不透明度
  下壁纸照样透过来，白字的对比度反而更高，看起来不再发灰。
- 浮层与弹窗内的次要文字用 `OVERLAY_SUBTLE`，常规文字用 `OVERLAY_TEXT`，
  比常驻面板的 `SUBTLE` / `MUTED_STRONG` 亮一档；`theme.rs` 的
  `overlay_contrast` 测试按「壁纸最亮的云 + 默认不透明度」守住 3.5:1。
- 旧版本恰好停在历史默认值（70% / 92% / 55% / 62%）的项会在 v1 → v3 迁移
  里换成新默认，用户自己拖出来的数值（哪怕更高）保持不变。
- 终端默认背景始终透明，透出壁纸与工作区玻璃（没有单独开关）；选区、搜索
  高亮和程序显式设置的背景仍不透明，所以 vim / tig 这类反色界面不会出现文字消失。
- 终端容器本身不再叠一层工作区玻璃，避免透明终端出现双重叠加。
- 玻璃色比背景色亮一档（`theme::GLASS_RGB`），并且工作区、标签栏、侧栏共用
  同一个色调：早期工作区用的是背景色本身，同色叠同色，滑杆拉到底也看不出变化。

## 三、新增界面时的检查清单

1. 是常驻结构面 → 玻璃；临时浮起 → 轻量浮层；阻断操作 → 模态弹窗 + 遮罩；
   贴在窗口最底层 → 背景。终端内容区 → 终端配色（设置 › 终端 › 配色）。
2. 底色从 `UiTokens::current(cx)` 或 `TerminalChrome::current(cx)` 取，禁止
   写字面量 alpha（`tests/ui_standards.rs` 会检查）。
3. 需要新的分类或参数时，先更新本文件与 `appearance_tokens.rs`，再改设置页；
   不要只为单个面板加滑杆。
4. 改完运行 `cargo test --test ui_standards` 与 `cargo test --test ui`。
